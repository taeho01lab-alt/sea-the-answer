# 1단계 | 데이터 선정과 출처 정리

## 목표와 출발점

해사 데이터의 담당 범위는 정형 운항 데이터, 데이터베이스, Python Tool입니다. 첫 단계에서는 파일을 많이 모으는 것보다 각 파일이 어떤 사실을 나타내는지 판별하는 데 집중했습니다. 실제 선박의 보고기간 합계와 가상 선박의 일별 운항 기록은 시간 단위와 사실성이 다릅니다. 이 둘을 무조건 합치면 실제 선박의 하루 운항을 관측한 것처럼 잘못 해석하게 됩니다.

원본 6개 파일을 대상으로 컬럼, 행 수, 시간 단위, 실제·합성 여부와 연결 가능한 식별자를 확인했습니다. 파일 선정은 현재 개발 목적에 맞는 범위를 정한 것이며, 공개 재배포나 자료 이용조건 검토를 완료했다는 의미는 아닙니다. 이 설명은 저장소의 전처리 코드, source_files 목록, summary.json과 검증 기록을 근거로 작성했습니다.

## 파일별 사용 결정

- DS-001과 DS-005: 실제 MRV 보고기간 집계 조회에 사용합니다. 연간 연료 사용량과 보고 CO2를 보여 주되 일별·항차별 자료로 분해하지 않습니다.
- DS-006: 합성 Noon을 일별 조회, 항차 연결, Tool 개발 테스트에 사용합니다. 실제 운항 자료와 동일한 신뢰 수준으로 취급하지 않습니다.
- DS-003: WPI 항구 기준정보로 보존합니다. 항구명이 비슷하다는 이유만으로 가상 항차와 자동 연결하지 않습니다.
- DS-004: SVD를 컬럼 설계 참고로 사용합니다. 운항 관측 건수에 포함하지 않습니다.
- DS-002: 마스킹 AIS를 참고자료로 보존합니다. 좌표 스케일을 추정 변환하거나 실제 IMO와 연결하지 않습니다.

이 결과 MRV 80,552행과 합성 Noon 4,380행이 운항 관측 전처리 대상이 됐습니다. AIS 55행과 WPI 3,807행은 목록과 체크섬을 보존했지만 본 관측 테이블 적재 대상으로 섞지 않았습니다.

## 출처를 보존한 방법

각 파일의 SHA256을 계산해 파일 내용이 바뀌었는지 비교할 수 있도록 했습니다. source_id는 Dataset ID와 파일 해시를 조합하고, 원본 파일명·출처 URL·행 수·헤더·용도·시간 단위를 source_files에 기록했습니다. 같은 이름의 다른 파일이 섞이는 것을 막기 위해 원본 폴더 검색 중 파일명이 중복되면 중단하도록 했습니다.

엑셀에 중복된 컬럼명이 있으면 이름만으로 덮어쓰지 않고 순서 배열로 헤더를 보존합니다. MRV 2025의 IMO와 Name은 선박·회사 영역에 중복되므로 선박 영역의 A/B열을 기준으로 식별했습니다. 이 처리가 없으면 회사 이름과 선박 이름이 뒤바뀔 수 있습니다.

## 재현과 인수인계

실행 구현은 scripts/prepare_maritime_data.py에 있습니다. 저장소 루트에서 원본 폴더를 --source로, 새 출력 폴더를 --out으로 지정합니다. 원본을 수정하지 않고 결과 폴더는 새 이름을 사용합니다. 기존 전처리 결과가 있으므로 단순 확인을 위해 다시 실행할 필요는 없습니다.

확인할 파일은 data/maritime-data/2026-09-30-v2/source_files.csv와 summary.json입니다. source_files.csv의 source_id, filename, sha256, data_origin, granularity, selection을 보면 어떤 자료가 어떤 목적으로 들어왔는지 추적할 수 있습니다. 원본 URL이 있다는 것만으로 이용 허락이 확인된 것은 아닙니다.

## 완료 기준과 남은 일

6개 원본의 목록과 체크섬, 실제·합성·참고·명세 분류가 마련됐습니다. 이후 단계는 이 분류를 보존하며 수행합니다. 실제 DWT, 연료종류, 공식 계수, 실제 항차 자료는 이 선정만으로 확보되지 않았으며 별도 보강 대상입니다. 엑셀 산출물은 선정·전처리 시점의 결과이고 최신 앱 구현 상태는 진행현황과 후속 단계 문서를 기준으로 확인합니다.
