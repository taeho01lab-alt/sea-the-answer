# 6단계 | 화면과 Agent 조회 연결

## 이번 단계의 범위

기존 읽기 전용 조회 API를 실제 사용자가 화면에서 호출하도록 연결하고, 조회 도우미가 같은 Tool을 실행하도록 구성했습니다. 기존 public 운항 조회와 혼동하지 않도록 관리자 메뉴에 정형 데이터 탭을 추가했습니다. 이 단계에서 공식 CO2/CII 계산, 자동 보고서 생성, 타 팀 Agent와의 외부 배포 통합은 수행하지 않습니다.

화면 구현은 web/app/role4-panel.js, 메뉴 연결은 web/app/page.js입니다. 서버의 도우미는 service/role4_agent.py, 진입점은 POST /api/role4/ask입니다. 기존 POST /api/role4/query를 통한 직접 조회도 함께 제공합니다.

## 화면을 만든 방법

실제 MRV를 선택하면 연도 범위, 합성 Noon을 선택하면 날짜 범위와 항차 ID를 보여 줍니다. 선박 ID는 선택 사항이며 비우면 기간 내 전체 선박입니다. 기존 운항 화면의 상단 선박·기간은 정형 데이터 탭에서 숨겨 서로 다른 조회 범위가 동시에 보이지 않게 했습니다.

결과는 전체 건수, 현재 페이지 구간, 연료 t, MRV 보고 CO2 t 또는 Noon 거리 nm를 표로 표시합니다. 원본 근거를 펼치면 원본 파일·행·해시·품질·provenance_json을 확인할 수 있습니다. numeric 문자열을 화면에서 다시 부동소수점으로 계산하지 않고 표시하며 결측은 결측으로 표시합니다.

필터나 질문을 바꾸면 이전 결과를 지워 이전 범위의 결과를 새 범위의 결과로 착각하지 않도록 했습니다. 자료 종류를 바꾸면 선박·항차 필터도 초기화합니다. 이전/다음 버튼으로 20행씩 이동하며 조회 중에는 기존 busy 처리를 통해 조작을 제한합니다. 빈 결과와 서버 오류는 별도 안내합니다.

## Agent Tool 실행 경로

도우미 입력은 question, scope, use_model입니다. scope는 5단계 조회 입력 계약을 그대로 재사용합니다. 서버에서 관리자 세션과 CSRF를 확인한 뒤 도우미가 query_role4를 실행합니다. 최종 수치와 행은 Python 조회 결과에서 나오며 모델이 계산하거나 작성한 값으로 대체하지 않습니다.

모델을 사용하지 않으면 rules 경로로 조회합니다. 모델이 설정되고 사용자가 모델 옵션을 선택하면 기존 Gateway.request를 통해 query_role4 함수 호출을 요청합니다. 이 함수의 모델 인수는 빈 객체만 허용합니다. 도구 이름, 호출 개수 1개, 인수 {}를 검사하고 통과할 때만 llm-tool-calling 경로로 표시합니다. 필터는 모델 응답이 아니라 이미 검증한 사용자 scope를 사용합니다.

모델 미설정·오류·잘못된 도구·필터 삽입은 경고를 남기고 같은 scope의 규칙 조회로 전환합니다. DB 행과 인증 정보는 모델 요청에 넣지 않으며, 사용자가 입력한 질문은 모델 사용 시 설정된 모델 서버로 전송됩니다. 외부 모델 허용 설정은 기존 Gateway 정책을 따릅니다.

## 지원하지 않는 요청과 의미적 한계

현재 도우미는 원본 기록 조회 전용입니다. 계산·등급·삭제·수정·등록·합계·평균·비교 등의 명시적 요청은 별도 도구를 실행하지 않고 지원 범위를 안내합니다. 이 규칙은 완전한 자연어 의도 분류기가 아닙니다. 분류를 통과한 문장도 항상 선택된 필터로만 조회하므로 DB 쓰기나 공식 계산을 수행할 수 없습니다.

질문 속 선박·연도를 자동으로 추출하지 않습니다. 따라서 질문에 2022년이라고 쓰면서 화면에서 2025년을 선택하면 실제 조건은 화면의 2025년입니다. 응답과 화면에 이 원칙을 명시했습니다. 현재 결과 요약은 서버가 만든 건수·표시 범위 설명이며 모델이 자연어로 원본을 분석한 답변이 아닙니다.

## 검증 방식과 완료 판정

테스트에서는 무로그인·일반 사용자·담당자 차단, 관리자 실행, CSRF 실패, 추가 SQL 필드 거절, 지원하지 않는 요청의 미실행을 확인합니다. 모의 HTTP 모델 응답으로 정상 함수 호출, 틀린 도구, 잘못된 JSON, scope 변경 시도와 규칙 대체 경로를 검증합니다. 실제 PostgreSQL과 격리된 인증 DB를 연결해 도우미 결과가 MRV 79,032행을 가리키는지도 확인합니다.

모의 모델 호출 테스트는 실제 LLM 추론 성공을 의미하지 않습니다. 실제 모델은 별도 구성·검증이 필요합니다. 실행 결과와 브라우저 확인 내용은 같은 폴더의 단계별 작업 안내 및 저장소 README에 기록합니다. 다음 과제는 팀 인터페이스 합의, 실제 모델 검증, 필요한 경우 선박 권한 매핑, 공식 계산 입력 보강입니다.

## 이번 실행 결과 (2026-09-30)

실제 PostgreSQL 테스트를 포함한 전체 서비스 63개 통과, Next.js 프로덕션 빌드 성공. TestClient의 httpx 폐기 예정 경고 1건이 있으며 실패는 없습니다. 브라우저에서 MRV 2020~2025년 조회 54,378건, 다음 페이지 21~40행, 합성 Noon 2025년 1월 조회 372건과 CII 등급 계산 요청 시 조회 미실행 안내를 확인했습니다.
