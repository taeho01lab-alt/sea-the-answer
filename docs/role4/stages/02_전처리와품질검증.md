# 2단계 | 전처리와 품질 검증

## 전처리의 목표

전처리는 원본을 그럴듯하게 채워 넣는 과정이 아니라, 조회·계산에 사용할 수 있는 값과 사용할 수 없는 값을 구분하는 과정으로 구현했습니다. 실제 MRV와 합성 Noon은 별도 CSV로 만들고 원본 레코드는 raw_records.jsonl에 보존했습니다. 관측 84,932행은 실제 MRV 80,552행과 합성 Noon 4,380행의 합입니다.

숫자는 Decimal로 해석하고 결측·음수·비정상 숫자를 구분했습니다. 빈칸과 N/A를 0으로 바꾸지 않았습니다. CSV의 빈 셀은 이후 DB의 NULL이 되며 원본 0은 그대로 0으로 남습니다. 쉼표가 소수점인지 천 단위인지 불확실한 값은 임의로 추정하지 않습니다.

## 실제 처리 순서

1. 원본 파일·시트·논리 행을 확인하고 안정적인 record_id를 부여했습니다. CSV의 행 번호는 줄바꿈 문자를 포함한 물리 줄 수가 아니라 논리 레코드 위치입니다.
2. 실제 선박은 REAL:IMO:번호, 합성 선박은 SYN:원본ID로 식별했습니다. 실제 IMO의 형식과 체크섬을 검사하지만 실제 발급 여부까지 확인한 것은 아닙니다.
3. 연료·CO2·거리·운항시간 등의 값을 파싱하고, 실패 원인과 원본 컬럼 정보를 provenance_json에 남겼습니다.
4. 선박·연도·보고유형을 기준으로 중복 후보와 Partial 보고서를 표시했습니다. 검토 대상은 보존하면서 기본 집계에서 제외했습니다.
5. 합성 일별 기록과 합성 항차의 선박 키 및 날짜 관계를 확인하고, 출처·품질 이슈와 함께 출력했습니다.

## 운항시간 24,654행 복구

과거 MRV의 정리된 운항시간 칸이 비어 있어도 원본 별칭 컬럼에 값이 남아 있는 경우가 있었습니다. resolve_hours는 알려진 원본 별칭을 확인해 유효한 값들이 서로 일치할 때만 채택합니다. 여러 컬럼의 값이 다르면 하나를 임의 선택하지 않고 conflicting_source_values로 남깁니다. 24,654행이 이 방법으로 복구됐고, 이는 추정값 생성이 아니라 원본 값 복원입니다.

## Partial·중복 후보·파생거리

Partial 1,520행은 보고기간이 일부인 자료이므로 Full과 단순 합산하지 않습니다. 이 중 75행은 같은 선박·연도·보고유형의 복수 레코드 그룹에 속합니다. 75행을 잘못된 중복으로 단정해 삭제하지 않았습니다. MRV 기본 집계 대상은 79,032행입니다.

거리 추정은 연료 t × 1000 ÷ 거리당 연료 kg/nm로 역산합니다. 연료 총량과 거리당 지표의 적용 범위가 일치하는지는 검증되지 않았기 때문에 distance_nm_estimate라는 이름으로 보존합니다. 이를 공식 CII 계산의 확정 거리나 독립 정답으로 사용할 수 없습니다. 실제 MRV의 DWT는 80,552행 모두 결측이며 역산 거리가 없는 행은 4,317행입니다.

## 검증 결과의 해석

합성 Noon은 4,380행, 238항차입니다. 거리 0인 557행은 정박 등 원본 의미를 보존해야 하므로 제거하지 않았습니다. 품질 이슈 26,249건 중 24,654건은 운항시간 복구 정보입니다. 이슈 총수를 실패 건수로 해석하면 안 됩니다. VALID는 지정 전처리 규칙을 통과했다는 뜻이며 실제 사실성·공식 규정 적합성 인증이 아닙니다.

원본 관측 행 수, record_id 고유성, 선박·항차 참조를 검사했습니다. 당시 숫자·기간·별칭 충돌 단위 테스트 3개 통과가 기록돼 있습니다. 재현 명령은 저장소에서 .venv/Scripts/python.exe scripts/test_prepare_role4.py입니다. 현재 단계 설명을 위해 원본 전처리를 다시 실행하거나 데이터를 다시 생성하지 않았습니다.
